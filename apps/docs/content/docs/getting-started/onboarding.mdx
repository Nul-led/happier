> **Availability:** Home-aware setup and Personal Home creation are available in the 0.3 development/preview line. Stable 0.2 keeps its released Relay-oriented onboarding.

Happier follows this high-level flow:

1. **Choose a Home** where your Account, credentials, sessions, settings, and data live.
2. **Sign in directly or use an Account Service**—Happier Cloud by default—to discover linked Homes.
3. **Use the desktop app as your control panel** (recommended; the web UI is best for status/management).
4. **Get a machine ready**:
   - **This computer**: configure the local background service from the app.
   - **Remote machine**: bootstrap it over SSH from the app, and optionally save the SSH target as a reusable Remote host.
5. **Optionally configure public ingress** for an operator-managed server. Personal Homes can use Iroh without a public address.

User guide: [Relay access](/apps/relay-access).

## Choose your setup

### Option A — Hosted (recommended to start)
You use Happier Cloud as the selected sign-in and Home-discovery service.

1. Open the desktop app (recommended) or the web app.
2. Choose **Happier Cloud** when the app asks how to find your Homes.
3. Sign in using one of the methods the service advertises.
4. Open the **Setup wizard** and choose **Set up this computer**.
   - This configures the local background service against the preferred Home you just entered.
   - If the app detects Home drift later, it shows a repair action instead of silently leaving the background service on another Home.
   - If you are restoring an already-signed-in device, use **Login with secret key instead** on the mobile login screen.

Optional CLI path:

```bash
# Node-free (recommended): install the CLI binary via the official installer
curl -fsSL https://happier.dev/install | bash
# The interactive installer starts setup automatically. Resume it if needed:
happier setup
```

The app-first setup is the recommended control-panel flow. The CLI is the terminal equivalent: it connects to one existing Home, performs any required interactive approval, registers the machine, and reconciles the service. `happier setup plan` only previews the steps.

Notes:
- The desktop app and the installer-installed CLI are self-contained; you do not need system Node/Yarn installed.
- If you prefer an npm workflow, see [CLI install](/apps/cli) (requires Node).

### Option B — Personal Home on your own computer or VPS

Create a Personal Home locally or over SSH, while keeping agent machines separate if you prefer:

1. Install the CLI, then create the Home:

   ```bash
   happier home create
   # or
   happier home create --ssh user@host
   ```

2. Follow the printed pairing guidance. Use `happier home pair-device` later to start a new short-lived QR/link session.

3. Optionally run `happier home link-account` so your selected Account Service can discover the Home later. The Account Service never carries normal Home traffic.

4. In the desktop app, decide which machine should run the background service:
   - **This computer**: use the **Setup wizard** → **Set up this computer**.
   - **Another machine**: use **Add machine over SSH** from the Machines settings screen or save a reusable Remote host first.

If you need a CLI fallback for a background-service host, connect it to the existing Home:

```bash
happier setup --home <saved-home> --skip-providers
```

This is the terminal guided executor for the same outcome as the app wizard.
If the machine was already set up and later drifted, run `happier doctor repair` instead of repeating first-time setup.

If you want to bootstrap a *remote machine* over SSH instead, use:

```bash
happier machine setup --ssh user@host
```
If you want to use a strict Iroh-only descriptor on a fresh machine, pass `--home-descriptor-file <path|->`. Manual HTTPS remains available through `--home-url`.

### Option C — Generic/operator server runtime

Operators can still deploy the generic server runtime with `happier relay host install`, Docker, or the runner. This is an advanced hosting path: it does not create an account, close signup, enroll a device, or convert the runtime into a Personal Home. Optional LAN, Tailscale, Cloudflare, and public HTTPS ingress remain documented under [Relay access](/apps/relay-access).

### One box that hosts a Home and runs Agents

Compose the two canonical commands rather than asking machine setup to create a Home:

```bash
happier home create --ssh user@host
happier --server <saved-home> machine setup --ssh user@host
```

The older `--install-relay-runtime` machine option remains an advanced compatibility path for generic runtime installation. It does not bootstrap a Personal Home.

Recommended for first setup:

- Check the Home identity before approving a new machine or device.
- Use the desktop app as the main control panel for background-service setup and repair actions.

## Multiple Homes (personal + company)

- The app and CLI support **multiple saved Home profiles**.
- Credentials/state are **scoped per Home**, so switching does not overwrite other accounts.
- Stable Home identity, not a mutable URL, keeps routing changes attached to the same saved Home.
- Web: you can switch the Relay **for this tab** or **make it the device default**.

### CLI: target a server per invocation

```bash
happier --server company auth login
happier --server company service start
```

### CLI: run multiple background services on one machine (one per Home)

```bash
happier --server personal service install
happier --server company service install
```

Then verify (cross-platform):

```bash
happier service list
happier --server personal service status
happier --server company service status
```

For complete profile/switching behavior and CLI reference, see [Features → Multi-server](/accounts/multi-server).
