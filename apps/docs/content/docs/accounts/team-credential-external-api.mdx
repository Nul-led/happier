---
title: Use a shared Provider from an external API client
description: Create a resource-scoped API key for a Team credential and use its OpenAI- or Anthropic-compatible HTTPS endpoint.
---

Use **External API access** when a compatible tool outside Happier needs to make
Provider requests through a Team credential resource. The upstream Provider
credential stays on the selected broker machine, while the external tool receives
only a resource-scoped Happier API key.

<Callout type="warn">
  Requests sent this way are **not end-to-end encrypted**. The raw provider
  request body — prompts, inputs, everything in it — passes through the Home in a
  form its operator can read. That is the trade this mode makes so that tools
  outside Happier can use a shared credential, and it is true of whichever Home
  serves the request. Use it only with a Home operator you trust with the request
  content, and keep sensitive work in ordinary Happier sessions.
</Callout>

> **Availability:** External API access is in the current unreleased 0.3 checkout, with [shared Team credentials](/accounts/team-credentials). Stable 0.2 has neither — check the version of the server binary you are running.

## Availability

External API access depends on [shared credentials for a
Team](/accounts/team-credentials), which depend on [Teams](/accounts/teams). All
three are per-Home capabilities that a self-hosted operator can turn off with
`HAPPIER_FEATURE_TEAMS__ENABLED`,
`HAPPIER_FEATURE_TEAMS_CREDENTIAL_RESOURCES__ENABLED`, and
`HAPPIER_FEATURE_TEAMS_CREDENTIAL_RESOURCES_EXTERNAL_API__ENABLED`.

The Home also needs a public address: `HAPPIER_PUBLIC_SERVER_URL` must be the
externally reachable `https://` origin that terminates its public traffic. A
disabled parent capability, missing feature information, or a public address that
is not HTTPS keeps the operation unavailable. Private use through Happier remains
separate and can continue without External API access.

## What you need first

You need:

- a Team credential resource configured for brokered use;
- permission to manage that resource;
- an active Team member who already has broker access to the resource;
- a resource policy that permits use without a Happier Team Session;
- a currently usable broker machine and credential source;
- route-grant signing configured on the Home. Every external request reaches the
  broker machine over a signed relay route, so a Home without
  `HAPPIER_PEER_MEDIATION_ROUTE_GRANT_SIGNING_KEY_ID` and
  `HAPPIER_PEER_MEDIATION_ROUTE_GRANT_SIGNING_PRIVATE_KEY` answers every request
  with *The broker is unavailable*, however healthy the broker machine itself is.
  [Local service previews](/self-hosting/local-service-previews) has the key
  generation and rotation steps; the same keys serve both features.

A resource that requires Team Session context or Team Session visibility cannot be
used by a Sessionless external client. Happier reports that state instead of
silently weakening the resource policy.

## Create an API key

1. Open **Settings → Teams**, choose the Team, then open **Shared credentials**.
2. Choose the credential resource and open **External API access**.
3. Enter a label that identifies the tool or installation.
4. Assign the key to an eligible Team member.
5. Choose an optional expiry: 30 days, 90 days, one year, or no expiry.
6. Create the key, then copy the base URL and API key from the one-time reveal.

The API key is a bearer secret. Happier stores only a digest and a safe display
prefix, and the full key is shown only once. Store it in the external tool's secret
manager or protected environment. Do not place it in source control, a URL, or a
shared command transcript.

Creating the first key turns External API access on for that resource. There is no
separate enable switch that can drift from the live keys.

## Configure the external client

Use the exact base URL shown by Happier. It ends in
`/api/provider-broker/v1` on the Home's public HTTPS origin.

The initial compatible routes are:

- OpenAI Responses: `POST /responses`;
- OpenAI Chat Completions: `POST /chat/completions`;
- Anthropic Messages: `POST /messages`;
- Anthropic token counting: `POST /messages/count_tokens`;
- the authorized model catalog: `GET /models`.

Authenticate with either `Authorization: Bearer <API key>` or the Anthropic-style
`x-api-key: <API key>` header. If a client sends both, they must contain the same
key. Query-string credentials, cookies, Account API Tokens, arbitrary Provider
paths, and browser CORS access are not accepted.

The resource's current membership, access, source, model, request, and usage-limit
policy is rechecked before each Provider request. Happier does not silently fall
back to a personal credential or another broker machine when that check fails.

## What the Home can read

Raw Provider request bodies traverse the Home's public HTTPS endpoint and are
readable by the Home operator. The connection is authenticated and encrypted in
transit with HTTPS, but the Provider payload is not end-to-end encrypted from the
external client to the broker machine — this is the known limitation stated at the
top of this page, and it is a property of the mode rather than a setting you can
change.

The external API key and the upstream Provider credential remain separate. The
Home authenticates the resource-scoped key, while the upstream credential is
injected only on the broker machine. Resource activity does not store prompts,
responses, request bodies, or secret values.

## Usage and limits

Every admitted inference request contributes one request-count fact, including a
request that later fails or is cancelled. Model listing and token-count helper calls
do not count as inference requests. The key's **Last used** value advances only
after an admitted use, not after a rejected authentication probe.

An external request has no Happier session and no agent to report on it, so its
token totals come from the provider's own response. Happier records them for
`/responses` and `/messages`, and for `/chat/completions` when the answer is not
streamed or your request asked for usage in the stream
(`stream_options.include_usage`). Happier never adds that option to your request
and never estimates the numbers, so a streamed chat completion without it is
recorded as a request whose tokens are unknown.

Cost is never recorded for these routes: no price list covers them, and an
unknown cost is left unknown rather than shown as $0.00. Happier therefore shows
unavailable or incomplete coverage instead of treating a missing measurement as
zero. Request-count limits remain available; token and cost limits are not
offered for external API use.

Usage is attributed to the resource, API key, and member to whom the key was
assigned. **Assigned to** identifies the credential owner; it does not prove which
person physically sent a request after the bearer was copied.

## Expire, replace, or revoke a key

- **Expiry:** an expired key stops authenticating. It remains visible as expired so
  you can identify and replace the affected installation.
- **Replace:** Happier creates a new key and reveals it once. Update the external
  tool, confirm that it works, then accept the offer to revoke the old key. This is
  a user-controlled rollout, not an atomic rotation.
- **Revoke:** revoking one key stops subsequent requests using that key. A request
  already admitted may finish.
- **Revoke every key:** removing the last key turns External API access off until a
  new key is created. Private Happier Sessions using the same resource are
  unaffected.

If the one-time value is lost, it cannot be revealed again. Create a replacement,
store the new value, update the client, and revoke the lost key. If a Team member is
removed, keys assigned to that membership are revoked as part of the removal flow.

## When it goes wrong

| What you see | What to check |
| --- | --- |
| External API access is unavailable | Confirm both feature switches are enabled and `HAPPIER_PUBLIC_SERVER_URL` is a reachable HTTPS origin. |
| The resource requires a Team Session | Change the resource policy deliberately, or use it from a Happier Team Session instead. |
| Authentication fails | The key may be mistyped, expired, revoked, assigned to an inactive member, or no longer entitled to the resource. Replace it if the saved value is uncertain. |
| The broker is unavailable | Restore the configured broker machine or credential source, and confirm the Home's route-grant signing keys are set — an unsigned Home reports this for every request. The API keys remain configured; do not recreate them just because the broker was temporarily offline. |
| A model or option is rejected | Review the resource's current request policy and authorized model catalog. |
| A usage limit is reached | Wait for the displayed UTC reset, or have a resource manager change the applicable limit. Requests already running may finish. |
