---
title: Terminal surface
description: Resolve an Agent-specific terminal launch plan.
---

Declare the terminal surface in `capabilities.surfaces` when the Agent can run
in a host terminal. Exactly one owner then implements
`resolveLaunch(request)`, chosen by the Agent's runtime kind:

- a `custom` runtime returns it as `AgentRuntime.surfaces.terminal`, alongside
  the sessions or execution-run runtime it already owns;
- a host-owned runtime — `acp` and the other declarative kinds — has no runtime
  object of its own, so it registers `terminal` on the same `definePlugin`
  Agent entry as its declaration.

The two are mutually exclusive. `definePlugin` rejects a `custom` Agent that
also registers a contribution, rejects a host-owned Agent that declares the
capability without one, and the host runtime lease fails closed if a runtime
and a contributed surface both arrive for one Agent.

The result contains the argument vector, optional launch environment, supported process presentation, and bounded result metadata. `argv` carries arguments only: the host resolves the Agent CLI executable and its own arguments and then appends `argv`, so repeating the executable name there launches it twice. The Agent leaf owns its CLI arguments and native breadcrumbs. The host owns terminal selection, process presentation, liveness, input policy, session continuity, and public state.

Terminal metadata does not grant write access to a running session. Do not write Happier transcript rows or session state directly; return the public launch plan and let the host apply supported result metadata.

For presentation of an already opened Session, the Developer Preview host uses
the Session's [selected-session terminal preparation](/plugins/agent-runtimes/session-runtime#selected-session-terminal-preparation).
The bare terminal surface is not a fallback that may launch a fresh conversation
when an exact resume is required.

## Provider CLI attach

When an Agent has a provider-native CLI attach mode, declare
`providerCliAttach` on the same `definePlugin` Agent entry. Its three required
callbacks have deliberately narrow jobs:

- `resolveTarget({ metadata, fallbackServerBaseUrl })` derives a string-only
  target from bounded Session metadata;
- `createArgs(target)` creates the Agent CLI argument vector; and
- `resolveReachability(target)` returns the HTTP or machine-local socket
  endpoint the host should probe, or `null` when no reachability probe applies.

Happier owns executable resolution, process creation, credentials, reachability
probing, connection custody, and Session continuity. OpenCode and Codex are the
current positive consumers of this public declaration.

## Prompt-submit verification

Declare `terminalPromptSubmitVerification` only when the Agent must recognize
its own terminal prompts around Happier's existing submit verification. The
policy may decide whether a prompt needs verification and inspect bounded
screen text before staging and after submit. It never receives a terminal
handle or owns submission, retry, cancellation, or cleanup. Claude is the
current positive consumer.
