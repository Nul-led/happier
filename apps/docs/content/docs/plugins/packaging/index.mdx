## Normal development flow

```bash
hdev plugins create my-plugin
cd my-plugin
hdev plugins dev
```

`plugins dev` asks the daemon to observe the trusted source closure. The
daemon-owned candidate lifecycle materializes declared development dependencies
and validates each affected candidate before adoption. It is the normal author
loop; authors and the CLI do not manage a second watcher, replacement, or
recovery state.

For a watcher-free development refresh, install the package root in
development mode and reload from that root:

```bash
hdev plugins install . --dev
hdev plugins reload
```

When the package root maps to multiple development plugins, or you reload from
another directory, use `hdev plugins reload com.example.my-plugin` to select
one. Invalid candidate source preserves the last accepted occurrence while the
daemon remains alive. After restart, current source must build and activate
again; development has no historical copied-source fallback.

## Validation and artifact flow

```bash
hdev plugins dev typecheck .
hdev plugins dev build .
hdev plugins test .
hdev plugins pack .
hdev plugins install <printed-archive-path> --kind archive
```

The author commands use Happier's managed toolchain. `plugins test` runs the
scaffold's focused `test/index.test.mjs` suite, activates the built module with
the public testkit, and runs the author-owned contracts without starting a daemon
or mutating installed plugin state. The untouched scaffold intentionally fails
one placeholder test until the author replaces it with a real contract.
`plugins test . --packed` creates that
selected-file archive, installs and trusts it in an authenticated disposable
daemon home, verifies currentness across daemon restart, and invokes a safe
empty-input CLI action when available. It never reads or mutates the user's
installed plugin state. `plugins pack` creates an npm-compatible selected-file
archive and digest sidecar. `plugins install` starts or reaches the active
daemon, prepares the candidate without executing it, and presents one concise
trusted-code and authority decision when approval is required. An
authority-neutral update does not repeat that decision.

The SDK remains on a prepublication hold in this checkout. Use the exact SDK
version selected by the scaffold or the release artifact supplied for a
preview; do not replace it with a workspace-internal import.
