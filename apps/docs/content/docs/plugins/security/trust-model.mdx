---
title: Trust model
description: Understand Happier's package-level trusted-code boundary.
---

Plugins are trusted code packages, not sandboxed extensions. A plugin can contain daemon code and React Native client code with the privileges of the Happier process or client realm in which it runs.

## Trusted-code decision

Happier validates and projects the cold manifest before importing executable
code. A first install from Settings or a catalog presents one concise decision
for the whole package, selected machine, and new authority or credential
access. An explicit CLI install command is the code-trust action for its exact
source:

```bash
hdev plugins install <archive-path> --kind archive
```

The CLI does not add a second trust ceremony. When a change needs a separate
authority or credential decision, interactive mode presents it and JSON mode
returns a typed pending decision. A manifest contribution, action, command, or
runtime registration cannot approve or widen that authority.

Trust the package only after reviewing its source, build inputs, dependencies,
declared host access, executable entrypoints, and UI artifacts. An
authority-neutral update does not prompt merely because bytes changed. New or
widened declared authority is shown as a delta and requires a decision.

## Development sources

`hdev plugins dev` starts the supported local development loop from the
plugin directory. The thin CLI selects the source; the daemon observes that
source, prepares author dependencies, validates each atomic candidate, and
adopts a process-local occurrence. An invalid candidate leaves the previous
occurrence serving only for that daemon lifetime. Development convenience does
not turn untrusted code into a sandbox or create immutable installed custody.

## Static projection

The host can show identity, contributions, settings, requested access, and installation review information from `.happier-plugin/plugin.json` before activation. Keep that file JSON-only and side-effect free.

## UI isolation

Packaged hosted web renders inside a host-constructed frame adapter where the host reports one, and is unavailable with a typed reason where it does not. React Native UI runs as trusted client code. Neither boundary changes the package-level trust decision, and the hosted-web isolation boundary does not sandbox the plugin's daemon entrypoint.
